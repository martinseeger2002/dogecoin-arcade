{# The details of an AI picture, filled in before it is inscribed (2026-10-27, SadFrog: "when a model makes an image for a user there should be a pipeline that easily allows them to inscribe right there. Have a prefilled template of a metadata that they can optionally fill out incase they want to make a small collection they can"). Included by the NFT inscriber (_account_inscribe.html) and the ord inscriber (create_ord.html). Both open it only when a picture came from the LLM tab's "Your pictures" (?pick=llm:[,...]); a file chosen from the disk gets none of this. What it writes is the JSON every collection on the arcade already uses (docs/collections.md, HashLips' shape: `inscriptions.collection_of` files a piece by a `name` of "Collection #12" and an integer `edition`), so a set made here is filed, listed and counted exactly like a set inscribed from a folder: {"name": "Night Frogs #2", "edition": 2, "description": "...", "attributes": [{"trait_type": "Model", "value": "qwen image 2.1"}, {"trait_type": "Mood", "value": "calm"}], "prompt": "..."} * Everything is optional. With nothing filled in and the model unticked there is no JSON at all, and a single picture goes on as a bare file, the same as before. * The model is a trait, ticked by default: it says how the picture was made, and costs a few bytes. * The prompt is NOT ticked by default (SadFrog, 2026-10-27): it stays on the chain for ever, and people may not expect what they typed to become public. Ticked, each piece carries its own prompt. * Every byte is paid for on the chain, so the preview shows the JSON exactly as it will go up. #}
