1 · Modules become tabs of the window

The tab row keeps the core on the left: Overview, Send, Receive, Transactions, Address book, and Messages, now part of the core. Every module that is switched on, that this person may use, and that they haven't hidden, gets its own tab after a divider. A module's page opens inside the window, so the menu bar, tabs and status bar stay put. If there are more tabs than fit, the rest go under “More ▾”.

3 · The operator opens or closes each module for everyone: Admin → Edition & modules

There are two switches per module. Running says whether this node runs it at all, as today. Who may use it says who gets its tab and its pages: nobody but you, signed-in users, or everyone including visitors. Closing a module to users removes its tab and makes its pages answer “not on this arcade” for them. The pages it serves to other arcades over the mesh aren't affected.

2 · Pick the colours

A theme is values, not CSS: eleven colours for light mode and eleven for dark. Put them in manifest.json:

{ "kind": "theme", "name": "Pumpkin",
  "light": { "win": "#f5eadc", "panel": "#fff8f0", "ink": "#1d1d1d",
             "sel": "#b85c2e", ... },
  "dark":  { "win": "#2b2622", ... } }

The guide checks each pair for contrast as you go and says which one is too faint.

5 · Admin is a tab of the same window, at the node's machine only

Today, opening Admin swaps the whole screen for a different top bar. Instead, Admin becomes the last tab of the window, with its sections as a second row inside it. The menu bar, the tabs and the status bar don't move. The tab appears only when the window is opened on the node's own machine (localhost); anyone opening the window from elsewhere never sees it.
