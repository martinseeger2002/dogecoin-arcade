Everything by API, with keys the operator gives out

Mockups for Window → Build → API. Nothing is built yet. Every page and action the arcade has belongs to one module, so a key opens exactly the modules its operator picks: Explore and Feed to read, say, or the Exchange to trade. A key works where the operator would, at the machine or from anywhere, and it never opens anything the arcade itself does not have. Under the API the arcade is unchanged: the same chains, wallet, mesh and rules.

Three things to decide before I build:
  1. Spending. Should a key ever be able to spend the node's coins? I'd allow it only when ticked, with a daily cap per chain, as drawn. The alternative is never: keys could read and post, but anything that spends would still need you at the window.
  2. Whose keys. Here only the operator makes keys, and a key acts as the node. Should signed-in users also get keys of their own, acting as their account within what you allow? They could come in a later step.
  3. From outside. A key works from anywhere over HTTPS by default, with “this machine only” or an address list per key. Is that right, or should keys work only on the machine and the LAN at first?
