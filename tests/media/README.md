# The pictures the account tests inscribe

`test_many_accounts.py` is the one place an account runs a whole collection, so
this is the one place there is real artwork. Everything else that needs a piece
makes one up: `test_collections.py` writes `b"\x89PNG" + bytes([edition]) * n`,
which is a length with a signature rather than a picture, and it is fine for
what that file is about.

## goofball/

A run of the HashLips Art Engine, one hundred unique 128x128 pieces with their
`dna` and their traits, as the engine leaves them: `json/_metadata.json`,
`json/<edition>.json`, `images/<edition>.png`. The engine's own output is 9 kB
to 19 kB a piece, which is more than one inscription carries, so every piece was
re-encoded here at 128 palette colours and nothing else was touched. That puts
the whole run at 3 kB to 5.7 kB an item, inside the one transaction a piece is
allowed to be.

Why the files are here rather than generated by the test: the sentence worth
proving is that an account ran a *collection*, and a build of a hundred
placeholders repeated with a different byte in it would prove the plumbing and
nothing about the pieces. The generator is not here, deliberately. It runs on
the box with the imaging models, and a node should never have to run it.

Why this folder has no `build/` in it: `.gitignore` ignores `build/`, and
`collections.find_build` is happy with a folder that holds `json/` and
`images/` directly, which is also what an uploaded folder looks like once the
browser has flattened it.

## icons/

The four icons the arcade's own tokens wear — `arcadecoin`, `cabinet`,
`joypad`, `shibacoin` — the byte-budget copies from `~/nft_pfp/token_icon/packed`
(192 to 256 px, 5.2 kB to 6.1 kB). A test that gives a token a face needs the
picture to be a real inscription, because the issuance carries its id and an id
that resolves to nothing is the failure the page's preview exists to catch.
